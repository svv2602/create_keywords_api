# Ограничение длины отзывов (1000 символов)

## 📋 Проблема

Необходимо контролировать длину генерируемых отзывов:
- **Максимальная длина**: 1000 символов
- **Толерантность**: 10% (допустимо до 1100 символов)
- **Действие при превышении**: автоматическое переписывание/сокращение

---

## ✅ Решение

### 1. Добавлено ограничение в промпт AI

В файле [universal_review_processor.rb:198](app/services/universal_review_processor.rb#L198) добавлена инструкция:

```ruby
instructions += "- КРИТИЧЕСКИ ВАЖНО: Максимальная длина отзыва - 1000 символов! Не превышай этот лимит!\n"
```

Это **превентивная мера** - AI сразу знает о лимите и старается не превышать его при генерации.

### 2. Автоматическая проверка и сокращение

В метод `process_for_uniqueness` добавлена проверка длины **после** генерации:

```ruby
# Финальная обработка с проверкой длины
final_review = finalize_review(processed_review, analysis, context)

# НОВОЕ: Проверка и переписывание если длина превышена
final_review = check_and_shorten_if_needed(final_review, context)
```

## 🔧 Реализованные методы

### 1. `check_and_shorten_if_needed`

**Назначение**: Проверка длины и автоматическое сокращение при превышении.

**Параметры**:
- `review` - текст отзыва
- `context` - контекст (пол, оценка, бренд и т.д.)
- `max_length` - максимальная длина (по умолчанию 1000)
- `tolerance` - толерантность (по умолчанию 0.10 = 10%)

**Алгоритм**:

```ruby
1. Вычисляем допустимый лимит: 1000 * (1 + 0.10) = 1100 символов

2. Если длина <= 1100:
   ✓ Возвращаем отзыв как есть

3. Если длина > 1100:
   a) Логируем предупреждение
   b) Создаем промпт для сокращения (build_shorten_prompt)
   c) Отправляем в AI для умного сокращения

   d) Проверяем результат:
      - Если успешно сокращен → возвращаем
      - Если AI не справился → жесткая обрезка (truncate_review_safely)

   e) При ошибках AI:
      - 1 повторная попытка
      - Fallback: безопасная обрезка
```

**Пример работы**:

```
Вход: 1349 символов
Выход: 550 символов ✓
```

### 2. `build_shorten_prompt`

**Назначение**: Создание промпта для AI с инструкциями по сокращению.

**Промпт включает**:
```
- Оригинальный отзыв
- Текущая длина и лимит
- Требование сохранить важные факты (бренд, модель, опыт)
- Требование убрать лишние детали
- Сохранение тональности и эмоций
- Сохранение пола автора (если указан)
- Сохранение тональности по оценке (если указана)
```

**Пример промпта**:

```
Перепиши следующий отзыв о шинах, СОКРАТИВ его длину, но сохранив основной смысл:

ОРИГИНАЛЬНЫЙ ОТЗЫВ: "..."

КРИТИЧЕСКИЕ ТРЕБОВАНИЯ:
- МАКСИМАЛЬНАЯ ДЛИНА: 1000 символов (сейчас 1349 - СЛИШКОМ ДЛИННЫЙ!)
- Сохрани все важные факты (бренд, модель, опыт использования)
- Убери лишние детали и повторения
- Сохрани тональность и эмоциональную окраску
- Сохрани мужской род
- Сохрани позитивную тональность (оценка 4.0/5)

Верни ТОЛЬКО сокращенный отзыв без комментариев.
```

### 3. `truncate_review_safely`

**Назначение**: Безопасная обрезка отзыва по границам предложений.

**Алгоритм**:

```ruby
1. Разбиваем на предложения (по .!?)
2. Добавляем предложения пока не превысим лимит
3. Если результат пустой или слишком короткий:
   - Обрезаем жестко до max_length
   - Добавляем "..." если не заканчивается на .!?
```

**Преимущества**:
- ✓ Не обрывает текст посередине предложения
- ✓ Сохраняет читабельность
- ✓ Всегда возвращает результат (fallback)

**Пример**:

```
Вход: 1349 символов
Выход: 930 символов (обрезано по границе предложения)
```

   │
   ├─ Попытка 2: AI сокращение (повтор)
   │  ├─ Успех → ✓ Возвращаем сокращенный
   │  └─ Неудача → Fallback
   │
   └─ Fallback: Безопасная обрезка
      └─ ✓ truncate_review_safely()

## 📈 Преимущества решения

### 1. Двухуровневая защита

**Превентивная**:
- AI знает о лимите ДО генерации
- Старается не превышать 1000 символов изначально

**Реактивная**:
- Автоматическая проверка ПОСЛЕ генерации
- Умное сокращение при превышении

### 2. Сохранение качества

- ✓ AI сокращает **осмысленно**, а не механически
- ✓ Сохраняются ключевые факты (бренд, модель, опыт)
- ✓ Сохраняется тональность и пол автора
- ✓ Убираются только лишние детали

### 3. Надежность

- ✓ 2 попытки AI сокращения
- ✓ Fallback на безопасную обрезку
- ✓ Всегда возвращает валидный результат
- ✓ Логирование всех действий

### 4. Гибкость

**Настраиваемые параметры**:
- `max_length` - максимальная длина (по умолчанию 1000)
- `tolerance` - толерантность (по умолчанию 10%)

**Легко изменить**:
```ruby
# Изменить лимит на 800 символов с 15% толерантностью
check_and_shorten_if_needed(review, context, 800, 0.15)
```

## 🔍 Мониторинг

### Логи Rails

Система логирует все важные события:

```ruby
# Предупреждение о превышении
Rails.logger.warn "Review too long: 1349 chars (limit: 1100). Shortening..."

# Успешное сокращение
Rails.logger.info "Successfully shortened review: 1349 → 550 chars"

# AI не справился
Rails.logger.warn "AI didn't shorten enough (1250), truncating..."

# Ошибки
Rails.logger.error "Shortening failed after retries: Connection timeout"
```

### Отслеживание в production

Рекомендуется мониторить:
- Частоту срабатывания сокращения
- Процент успешных AI сокращений
- Процент fallback на жесткую обрезку
- Ошибки AI при сокращении

## 📝 Технические детали

### Оценка токенов

```ruby
# Для русского языка: примерно 4 символа = 1 токен
estimated_tokens = (max_length / 4.0).round  # 1000 / 4 = 250 токенов

# Запрашиваем с запасом
max_tokens = estimated_tokens * 2  # 500 токенов
```

### Разбивка на предложения

```ruby
# Регулярное выражение захватывает знаки препинания
sentences = review.split(/([.!?]+)/)

# Результат: ["Текст1", ".", "Текст2", "!", "Текст3", "."]

# Собираем обратно по 2 элемента (текст + знак)
sentences.each_slice(2) do |sentence, punctuation|
  # ...
end
```

### Толерантность

**Почему 10%?**
- Слишком строго (0%) → частые срабатывания, лишняя нагрузка на AI
- Слишком мягко (20%+) → теряется смысл лимита
- **10%** - золотая середина:
  - Допускает естественные вариации длины
  - Предотвращает явные превышения
  - Снижает количество переписываний

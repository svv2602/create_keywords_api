# Добавление дат отзывов с учетом сезонности

## 📋 Проблема

Модераторы выявили критическую проблему с несоответствием дат в генерируемых отзывах:

### Пример проблемы:
**Текст отзыва (июль)**: "Недавно купил зимние шины..."
**Проблема**: Зимние шины обычно не покупают летом!

Аналогично для летних шин зимой. Это выглядит неестественно и снижает доверие к отзывам.

---

## ✅ Решение

Система теперь генерирует:
1. **review_date** - дата написания отзыва (последние 3 месяца)
2. **purchase_date** - дата покупки с учетом сезонности шин
3. **time_description** - естественное описание времени покупки

### Ключевые принципы:

#### 1. Сезонность покупки
- **Зимние шины** (season: 2): покупка в сентябре-январе
- **Летние шины** (season: 1): покупка в марте-августе
- **Всесезонные** (season: 3): покупка круглый год

#### 2. Естественность времени
AI получает **вагное описание** вместо точных дат:
- "недавно", "на днях"
- "месяц назад", "пару месяцев назад"
- "прошлой зимой", "летом"

#### 3. Предупреждение о несезонности
Если отзыв пишется не в сезон (например, зимние шины летом), AI получает специальное предупреждение, чтобы не писать "купил вчера".

#### Новые методы (добавлены в конец класса):

##### `generate_review_dates(tire_season)`

Главный метод генерации дат.

**Параметры:**
- `tire_season` - сезон шин (1=летние, 2=зимние, 3=всесезонные)

**Возвращает:**
```ruby
{
  review_date: "2025-11-15",           # ISO формат
  purchase_date: "2025-09-20",         # ISO формат
  time_description: "пару месяцев назад"  # Естественная формулировка
}
```

**Логика:**
1. Генерирует `review_date` - случайная дата за последние 90 дней
2. Вызывает `find_suitable_purchase_date` для подбора даты покупки
3. Вызывает `format_time_period` для описания времени
4. Возвращает хэш с тремя ключами

##### `find_suitable_purchase_date(review_date, tire_season)`

Подбирает дату покупки с учетом сезонности.

**Параметры:**
- `review_date` - дата отзыва (Date object)
- `tire_season` - сезон шин (1, 2 или 3)

**Алгоритм:**

1. **Определяет допустимые месяцы покупки:**
   ```ruby
   purchase_months = case tire_season
   when 2  # зимние
     [9, 10, 11, 12, 1]
   when 1  # летние
     [3, 4, 5, 6, 7, 8]
   else    # всесезонные
     (1..12).to_a
   end
   ```

2. **Ищет подходящую дату в последние 365 дней:**
   - Начинает с `review_date` и идет назад
   - В 30% случаев выбирает случайную дату в допустимом сезоне (для вариативности)
   - В 70% случаев ищет первую подходящую дату

3. **Возвращает:** Date object или nil

**Примеры:**

```ruby
# Зимние шины, отзыв в июле
review_date = Date.new(2025, 7, 15)
purchase_date = find_suitable_purchase_date(review_date, 2)
# => Вернет дату из [сентябрь-январь] прошлого сезона
# Например: 2024-12-10 (декабрь прошлого года)

# Летние шины, отзыв в ноябре
review_date = Date.new(2025, 11, 20)
purchase_date = find_suitable_purchase_date(review_date, 1)
# => Вернет дату из [март-август] этого года
# Например: 2025-08-15 (август)
```

##### `format_time_period(review_date, purchase_date)`

Генерирует естественные формулировки времени.

**Параметры:**
- `review_date` - дата отзыва
- `purchase_date` - дата покупки

**Логика по временным периодам:**

```ruby
months_diff = ((review_date.year - purchase_date.year) * 12 +
               review_date.month - purchase_date.month)

case months_diff
when 0  # < 1 месяца
  ["недавно", "на днях", "только что"].sample

when 1  # 1 месяц
  month_name = RUSSIAN_MONTHS_PREPOSITIONAL[purchase_date.month]
  ["месяц назад", month_name].sample
  # Примеры: "месяц назад" или "в октябре"

when 2  # 2 месяца
  ["пару месяцев назад", "два месяца назад"].sample

when 3..5  # 3-5 месяцев
  season = get_purchase_season(purchase_date)
  ["несколько месяцев назад", season, "#{months_diff} месяца назад"].sample
  # Примеры: "несколько месяцев назад", "летом", "4 месяца назад"

when 6..8  # 6-8 месяцев
  season = get_purchase_season(purchase_date)
  ["полгода назад", season].sample
  # Примеры: "полгода назад", "весной"

else  # 9-12 месяцев
  month_name = RUSSIAN_MONTHS_PREPOSITIONAL[purchase_date.month]
  season = get_purchase_season(purchase_date)
  [month_name, season, "#{months_diff} месяцев назад"].sample
  # Примеры: "в январе", "зимой", "10 месяцев назад"
end
```

**Константы месяцев:**
```ruby
RUSSIAN_MONTHS_PREPOSITIONAL = {
  1 => "в январе", 2 => "в феврале", 3 => "в марте",
  4 => "в апреле", 5 => "в мае", 6 => "в июне",
  7 => "в июле", 8 => "в августе", 9 => "в сентябре",
  10 => "в октябре", 11 => "в ноябре", 12 => "в декабре"
}
```

#### Новые методы:

##### `build_date_instructions(context)`

Создает инструкции для AI по работе с датами.

**Параметры:**
- `context` - хэш с полным контекстом (включая review_date, purchase_date, time_description, season)

**Логика:**

1. **Базовые инструкции** (всегда):
   ```
   - ВАЖНО: Шины были куплены [time_description]
   - Используй естественные формулировки времени: "недавно", "пару месяцев назад", "прошлой зимой" и т.д.
   - НЕ указывай точные даты покупки или отзыва
   ```

2. **Предупреждения о сезонном несоответствии:**

   **Зимние шины летом** (июнь, июль, август):
   ```
   - ВНИМАНИЕ: Сейчас лето, но отзыв о зимних шинах - не пиши "купил вчера" или "на днях купил зимние шины летом"
   - Уместно упомянуть покупку осенью/зимой прошлого сезона
   ```

   **Летние шины зимой** (декабрь, январь, февраль):
   ```
   - ВНИМАНИЕ: Сейчас зима, но отзыв о летних шинах - не пиши о недавней покупке летних шин зимой
   - Уместно упомянуть покупку весной/летом прошлого сезона
   ```

**Пример итогового промпта:**

```
- Обязательно используй бренд Michelin в отзыве
- Обязательно упомяни модель X-Ice в отзыве
- ВАЖНО: Пиши от лица мужчины, используй мужской род
- КРИТИЧЕСКИ ВАЖНО: Итоговая оценка 4.5 из 5 - текст должен быть восторженный
- ВАЖНО: Шины были куплены прошлой осенью
- Используй естественные формулировки времени: "недавно", "пару месяцев назад", "прошлой зимой" и т.д.
- НЕ указывай точные даты покупки или отзыва
- ВНИМАНИЕ: Сейчас лето, но отзыв о зимних шинах - не пиши "купил вчера" или "на днях купил зимние шины летом"
- Уместно упомянуть покупку осенью/зимой прошлого сезона
```

## 📝 Технические детали

### Временные рамки

| Параметр | Значение | Примечание |
|----------|----------|------------|
| Дата отзыва | Последние 90 дней | `Date.today - rand(0..90).days` |
| Дата покупки | До 365 дней назад | Поиск в пределах года |
| Сезон покупки зимних | Сентябрь-Январь | Месяцы: 9, 10, 11, 12, 1 |
| Сезон покупки летних | Март-Август | Месяцы: 3, 4, 5, 6, 7, 8 |

### Вариативность

Система использует случайность для реалистичности:

1. **Дата отзыва**: случайная из последних 90 дней
2. **Дата покупки**: 30% - случайная в сезоне, 70% - ближайшая к отзыву
3. **Формулировка времени**: случайный выбор из массива вариантов

Это обеспечивает разнообразие отзывов и избегает повторяющихся паттернов.

### Локализация

Все формулировки времени на русском языке:
- Месяцы в предложном падеже ("в январе", "в мае")
- Сезоны ("зимой", "летом", "весной", "осенью")
- Временные маркеры ("недавно", "пару месяцев назад")

## 🐛 Граничные случаи и обработка ошибок

### 1. Невозможно найти подходящую дату
```ruby
purchase_date = find_suitable_purchase_date(review_date, tire_season)
# Возвращает nil, если не найдено за 365 дней

if purchase_date.nil?
  # Система корректно обработает nil
  # time_description тоже будет nil
  # AI инструкции по датам не будут добавлены
end
```

### 2. Некорректный сезон шин
```ruby
case tire_season
when 2 then [9, 10, 11, 12, 1]  # зимние
when 1 then [3, 4, 5, 6, 7, 8]  # летние
else (1..12).to_a               # любой другой - всесезонные
end
```

### 3. Парсинг дат в AI инструкциях
```ruby
review_date = Date.parse(context[:review_date]) rescue Date.today
# Если парсинг не удался - используется текущая дата
```
